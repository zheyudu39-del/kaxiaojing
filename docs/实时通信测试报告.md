# 交流大厅 实时通信测试报告

**测试时间**：2026-10-02
**测试脚本**：`工具/socket-latency-test.js`
**测试对象**：Socket.IO 实时通信（`server/src/socket/index.ts` + `lobbyService`）

---

## 一、测试方法

脚本模拟**两个真实用户**（各自注册 + 登录拿到 JWT），建立两条独立的 Socket.IO 连接，加入大厅房间后互发消息，测量端到端延迟。

```
用户A ──emit('send-lobby-message')──▶ 服务端 ──io.to('lobby').emit('new-lobby-message')──▶ 用户A + 用户B
                     ▲                                                                        │
                     └──────────────── 测量：从 emit 到 on 的耗时 ─────────────────────────────┘
```

| 测试项 | 方法 |
|---|---|
| **延迟** | 消息内容里埋唯一标记，接收端轮询匹配到该标记即记录时间戳（微秒精度 `hrtime`） |
| **双向性** | A→B 与 B→A 各测 N 轮，验证两个方向都能收到 |
| **可靠性** | 统计期望条数 vs 实际到达条数 |
| **重复检测** | 在**每个用户自己的接收列表内**查重（不能跨用户合并——同一条消息本来就会广播给双方） |
| **顺序性** | 一次连发 10 条，校验接收顺序 |

---

## 二、测试结果（30 轮双向）

### 延迟

| 方向 | 样本 | 最小 | P50 | P95 | 最大 | 平均 |
|---|---|---|---|---|---|---|
| **A → B**（B 收到） | 30 | 1.2 ms | **1.5 ms** | 7.8 ms | 7.8 ms | **3.1 ms** |
| **B → A**（A 收到） | 30 | 1.0 ms | **1.4 ms** | 7.3 ms | 8.0 ms | **3.1 ms** |
| A 自己回显 | 30 | 1.1 ms | 1.4 ms | 7.6 ms | 7.7 ms | 3.0 ms |

> 20 轮复测结果一致（A→B 平均 3.2 ms，B→A 平均 3.1 ms）。

### 可靠性

| 指标 | 结果 |
|---|---|
| 期望到达 | 60 条 |
| 实际到达 | 60 条 |
| **丢失** | **0 条** |
| **送达率** | **100.0%** |
| 重复 | 0 条 |

### 顺序性

连发 10 条 → B 收到 10 条，**顺序完全正确** ✅

---

## 三、结论

| 项 | 结果 |
|---|---|
| **双向实时通信** | ✅ **正常** —— A、B 双方都能实时收到对方消息 |
| **平均延迟** | **3.1 ms** |
| **延迟评价** | **优秀**（远低于 50 ms 阈值） |
| **消息丢失** | ✅ 无 |
| **消息重复** | ✅ 无 |
| **顺序性** | ✅ 正确 |

**P50 约 1.4 ms** 意味着典型的"一人打字、另一人立刻看到"延迟几乎不可感知。
**P95 约 7.5 ms** 的毛刺来自 Node 事件循环的调度抖动，属正常范围。

### 说明

本测试为**本机回环**（客户端与服务端都在同一台机器），延迟只包含：
服务端处理 + Socket.IO 序列化 + 事件循环调度。

**真实跨网络场景**还需叠加网络往返（RTT）。参考量级：

| 场景 | 预计总延迟 |
|---|---|
| 同城内网 | 3 ~ 15 ms |
| 跨省公网 | 30 ~ 80 ms |
| 跨国 | 150 ~ 400 ms |

即便按最差的跨国场景估算，也完全满足聊天室"实时"的体验要求。

## 四、复现方式

```bash
# 1. 启动后端
cd kaxiaojing/server
node dist/index.js

# 2. 跑测试（socket.io-client 来自 web/node_modules）
NODE_PATH="D:/kaxiaojing-backup/kaxiaojing/web/node_modules" \
  node 工具/socket-latency-test.js 30
```

参数：第一个参数为轮数（默认 30）。也可用 `SOCKET_URL` 指定服务端地址。

> ⚠️ 脚本会注册两个测试账号并写入大厅消息，测试后请还原数据库：
> `cp /tmp/db-before-sockettest.db server/data/competition.db`
