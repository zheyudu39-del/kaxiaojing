## 三、🐛 测试中发现并修复的 2 个真实 Bug

两个都属于**同一类缺陷：缺少输入校验，导致 `undefined` 被绑进 SQL 而 500**。

### Bug 1：资源评分接口缺校验

**位置**：`server/src/services/resourceService.ts` → `rateResource()`

```js
// 修复前
if (rating < 1 || rating > 5) throw new Error('INVALID_RATING');
```

**问题**：当 `rating` 为 `undefined` 时，`undefined < 1` 和 `undefined > 5` **都是 false**，
校验被完全绕过，`undefined` 直接写入数据库 → 500。

**触发方式**：`POST /api/resources/1/rate` 且 body 为 `{}`（或任何缺 `rating` 的请求）。

**修复**：
```js
const r = Number(rating);
if (!Number.isFinite(r) || r < 1 || r > 5) throw new Error('INVALID_RATING');
```

### Bug 2：反馈状态更新接口缺校验

**位置**：`server/src/services/feedbackService.ts` → `updateStatus()` + `server/src/routes/feedback.ts`

**问题**：`status` 未做白名单校验，`undefined` 直接进 SQL；数据库虽有 `CHECK` 约束，
但绑定阶段就抛异常 → 500。

**触发方式**：`PATCH /api/feedback/admin/:id/status` 且 body 为 `{}`。

**修复**：服务层增加白名单校验（`pending/processing/resolved/closed`），路由层捕获后返回 **400** 并给出可选值提示。

> 这两个缺陷**类型检查发现不了、只看代码也不易察觉**，只有真正发请求打出来才会暴露。

## 五、注意事项（环境坑）

1. **后端限流会伪装成"功能坏了"**
   `express-rate-limit` 默认 200 次/15 分钟。快速扫页会触发 429，
   前端表现为「数据全空 + 登录态被清」，看起来像代码 bug。
   测试/联调时用：
   ```bash
   RATE_LIMIT_MAX=100000 AUTH_RATE_LIMIT_MAX=100000 node dist/index.js
   ```

2. **测试会写数据**
   脚本会注册测试账号。测试后请还原数据库：
   ```bash
   cp /tmp/db-before-api-test.db server/data/competition.db
   ```
