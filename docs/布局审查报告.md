# 前端布局合理性审查报告

审查对象：`kaxiaojing/web`（Vite + React 18 + Ant Design 5）
审查方式：Playwright 在真实浏览器中渲染，按多档视口逐页测量几何数据（横向溢出、元素越界、固定栏遮挡、控件对齐、文本裁剪、兄弟重叠），辅以代码审查。
测量视口：**375×812（手机）/ 768×1024（平板）/ 1440×900（桌面）**
覆盖页面：22 个公开页面 + 受保护页面代码审查

## 二、问题详情与修复

### 问题 1：移动端顶部导航溢出（严重）

**现象**：375px 视口下，`document.documentElement.scrollWidth = 540px`，页面出现横向滚动条。
顶部导航项一直排到 788px（排行榜 / 经验分享 / 交流大厅 / 问答 / 招募广场 / 更多），全部被挤出屏幕。

**根因**：`AppHeader` 完全没有移动端分支。导航项按桌面全量渲染（`PRIMARY_LIMIT = 8`），
搜索框固定 `width: 200`。父级 `nav` 虽有 `overflow: hidden`，但只是裁剪，不解决占用宽度。

**修复**（`layouts/AppHeader.tsx`）：
- 移动端引入 `useIsMobile()`，导航改收进「导航」下拉（`CompassOutlined`）
- 搜索框在移动端改为图标按钮，点击后展开 130px 输入框
- 隐藏 logo 文字、AI 助手入口、注册按钮；用户名字改为仅头像
- 移动端间距 `gap` 16 → 8，padding 16 → 10

### 问题 2：聊天页输入框被底部导航遮挡（严重）

**现象**：375×812 下 `/lobby`，聊天区底边 811px，底部导航顶边 756px，**输入框被压住 55px**，用户无法输入。

**根因**：`.chat-page` 用写死的 `calc(100vh - 64px - 48px)` 计算高度，
既没有减掉移动端底部导航（56px），也没有考虑页面外层还有 `PageHeader` + `Card` 的占用。
`Lobby.tsx` / `TeamForum.tsx` 还各自用内联 `calc(100vh - 240px)` 覆盖，逻辑三处不一致。

**修复**：
- `styles/global.css` 新增 `.fill-viewport`（撑满可视高度）+ `.chat-page--flex`（占据剩余空间）
- 改用 **flex 自适应**替代 `100vh` 硬算式，`PageHeader` / `Card` 高度变化自动吸收
- `Lobby.tsx` / `TeamForum.tsx` / `AiAssistant.tsx` 三处统一套用，移除内联覆盖

修复后实测：聊天区底边 743px < 底栏顶边 756px，输入框完整可见。

### 问题 3：响应式断点不一致（中）

`hooks/useMediaQuery.ts` 的 `useIsMobile()` 用 **991px**，
而 `styles/global.css` 的 `.page-container` 安全区用 **767px**。
在 **768–991px** 区间会出现「底部导航已显示、内容区却没预留安全区」的错位。

**修复**：`global.css` 断点统一为 991px，与 `useIsMobile()` 对齐。

### 问题 4：排行榜表格撑破窄屏（中）

`/ranking` 在 375px 下页面宽 417px。表格三个数值列各 `width: 100`，未设置 `scroll`。

**修复**（`pages/ranking/Ranking.tsx`）：列宽 100 → 80，并加 `scroll={{ x: 'max-content' }}`。

### 问题 5：ECharts 不响应容器宽度变化（中）

`components/Chart.tsx` 只在 `window.resize` 时调用 `resize()`。
但 Tab 切换、侧栏折叠、视口断点切换都会改变容器宽度却不触发 `window.resize`，
图表画布停留在旧宽度（实测 446px）溢出父容器。

**修复**：改用 `ResizeObserver` 监听容器自身尺寸，并在容器隐藏（`clientWidth === 0`）时跳过，
另加 120ms 延时补一次 resize 兜底。

### 问题 6：资源库表格固定宽度偏大（轻）

`/resources` 设 `scroll={{ x: 1100 }}`，而桌面 1440 下卡片内容区仅 1072px，
导致**桌面端也恒有横向滚动条**。

**修复**：压缩列宽（竞赛 200→160、上传者 110→100、类型 90→80、大小 90→80、
下载 80→72、评分 150→130、时间 170→150、操作 90→84），`scroll.x` 1100 → 940。
该列数较多，窄屏横向滚动属预期行为。

## 四、审查工具

| 文件 | 说明 |
|------|------|
| `工具/ui-layout-audit.js` | 浏览器内执行的布局审计脚本，返回结构化 JSON |
| `工具/ui-layout-sweep.sh` | 多视口批量扫页驱动脚本 |
| `工具/ui-report.js` | 审计结果紧凑报告输出 |

审计维度：页面横向溢出、元素越界、固定栏遮挡、侧栏/内容区结构校验、
顶部导航压缩、同行控件对齐、文本裁剪、兄弟元素重叠、内容区过窄、页面过空。

**排除的误报**：
- antd 表格固定列（`fixed: left/right`）覆盖滚动列属正常设计
- antd Tabs 标签栏横向滚动属正常设计
- 表格内相邻单元格不做重叠判定
- 每次导航后重设视口再测量，消除「宽视口渲染完成→缩小→立即测量」的时序竞态伪影
